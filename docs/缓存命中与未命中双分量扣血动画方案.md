# 缓存命中与未命中双分量扣血动画方案

## 目标

一次模型调用可能同时包含缓存命中输入、缓存未命中输入和输出 token。插件应在同一次扣费反馈中同时展示对应费用分量，并保证余额只按该调用的总费用扣减一次。

本方案已按下述兼容事件契约实装。最终视觉采用三分量共同轨道：余额按总费用立即且只扣一次，分量只负责动画反馈。

## 已确认的数据基础

DeepSeek Harness 已提供互斥的用量字段：

- `inputTokens`：缓存未命中的输入 token。
- `cacheReadTokens`：缓存命中的输入 token。
- `cacheWriteTokens`：缓存写入 token；DeepSeek 当前通常不提供，但 Harness 已预留。
- `outputTokens`：输出 token，已包含 reasoning token。

插件现有计价器已经分别计算输入、缓存和输出费用，因此不需要修改 DeepSeek Harness 上游适配器。需要调整的是 Host 的扣费事件结构和 Client 的事件合并方式。

## 当前问题

当前每次调用只产生一个 `damageKind`：

```ts
type DamageKind = 'normal' | 'miss'
```

只要本次调用存在 `inputTokens` 或 `cacheWriteTokens`，整笔费用就会被标记为 `miss`。当一次调用同时有缓存命中和未命中时，命中部分会被吞进“未命中”动画。Client 还会把一次轮询拿到的所有事件合并成单条飘字，进一步丢失费用构成。

## 推荐事件契约

采用增量兼容字段，不删除现有的 `cost` 和 `damageKind`：

```ts
interface ChargeComponent {
  tokens: number
  cost: number
}

interface ChargeBreakdown {
  cacheHit: ChargeComponent
  cacheMiss: ChargeComponent
  output: ChargeComponent
}

interface ChargeEvent {
  seq: number
  timestamp: number
  cost: number
  damageKind: 'normal' | 'miss'
  breakdown?: ChargeBreakdown
}
```

费用映射：

```text
cacheHit.tokens = cacheReadTokens
cacheHit.cost = cacheReadTokens × cacheHit 单价

cacheMiss.tokens = inputTokens + cacheWriteTokens
cacheMiss.cost = inputTokens × input 单价
               + cacheWriteTokens × input 单价

output.tokens = outputTokens
output.cost = outputTokens × output 单价

event.cost = cacheHit.cost + cacheMiss.cost + output.cost
```

计价器内部应把当前合并在 `costCache` 中的缓存读取与缓存写入费用拆成 `costCacheRead` 和 `costCacheWrite`，再由旧字段 `costCache` 汇总两者。这样不会用四舍五入后的总额反推分量。

`damageKind` 继续保留：只要 `cacheMiss.cost > 0` 就为 `miss`，否则为 `normal`。旧 Client 仍能按整笔费用播放现有动画；新 Client 优先读取 `breakdown`。

## Client 播放规则

一次轮询拿到事件后执行两个彼此独立的动作：

1. 余额更新：对所有有效事件的 `event.cost` 求和，只调用一次余额扣减。`breakdown` 仅用于解释和动画，绝不参与第二次扣款。
2. 动画更新：分别汇总本轮的 `cacheHit.cost`、`cacheMiss.cost` 和 `output.cost`，非零分量进入同一个 FIFO 队列。首条立即发射，后续每隔 200ms 发射。

推荐默认视觉：

| 分量 | 文案 | 动画强度 | 轨道 |
| --- | --- | --- | --- |
| 缓存命中 | `命中 -0.00xx¥` | 普通命中脉冲，1000ms / 90px | 共同轨道 |
| 缓存未命中 | `未命中 -0.00xx¥` | 大号红字、短促横向冲击、更强余额回弹，1250ms / 132px | 共同轨道 |
| 输出 | `输出 -0.00xx¥` | 小号、低强调红色，1000ms / 90px | 共同轨道 |

三种反馈都锚定余额数字区域，不增加余额与“峰/闲”状态之间的间距，不使用红色冲击圈。它们共用同一轨道并允许自然覆盖；队列首条立即开始，后续固定间隔 200ms，最多同时保留最近三条飘字。

UI 参考：

- ANIMATA：参考短时并发、错峰进入和快速退场的节奏。
- Creative Tim Badge：参考紧凑的状态标签层级；“命中 / 未命中 / 输出”仅作为小标签，不改变余额栏主体布局。

## 输出费用策略

输出费用既不是缓存命中，也不是缓存未命中。推荐默认单独弱化显示，以保持本地计费可解释性。后续设置页可以提供：

```ts
type OutputDisplay = 'separate' | 'merge-with-miss' | 'hidden'
```

- `separate`：推荐默认值，费用构成最清楚。
- `merge-with-miss`：界面只显示两条，但“未命中”金额会包含输出费用，需要在设置说明中明确。
- `hidden`：不显示输出飘字，但余额仍扣除输出费用。

## 边界校验与回退

Client 在 API 边界校验：

- `cost`、各分量 `tokens` 和 `cost` 必须是有限非负数。
- 分量费用之和与 `event.cost` 的误差不得超过 `max(1e-9, event.cost × 1e-6)`。
- `breakdown` 缺失或校验失败时，忽略整组分量，回退到现有 `damageKind + cost` 动画。
- 首次建立 `seq` 基线时仍跳过历史事件，避免余额重复扣减。
- 60 秒余额接口继续作为权威校准源；本地扣减只提供即时视觉反馈。

## 实施步骤

1. 扩展 `pricing.ts` 的内部费用明细，独立计算 cache read 和 cache write 费用，并保留原汇总字段。
2. 扩展 `charge.ts` 的 `ChargeEvent`，让 `recordCharge` 接收可选 `breakdown`。
3. 调整 `collector.ts`，用同一次计价结果构造总费用与三个动画分量。
4. 调整 `BalanceWidget.tsx`，新增边界校验、分量聚合、共同轨道 FIFO 动画队列；保留旧事件回退。
5. 为价格映射、分量和总额一致性、旧事件回退、混合命中调用、同轮多事件聚合执行专项验证。
6. 在完整 Harness 构建 Client bundle，分别用纯命中、纯未命中、命中加未命中、含输出、多事件轮询五组数据做运行时冒烟。
7. 同步本地 Harness 与 GitHub 发布副本，更新 README/GIF 后再推送。

## 验收标准

- 同一调用同时有 `cacheReadTokens > 0` 和 `inputTokens > 0` 时，能同时看到“命中”和“未命中”两条飘字。
- 输出费用默认以弱化的第三条飘字显示，不被误标为未命中。
- 动画显示费用分量之和与余额变化量一致。
- 同一批事件无论出现几条动画，余额只扣一次总费用。
- 旧 Host 与新 Client、新 Host 与旧 Client 都能继续工作。
- 余额数字与峰闲状态保持当前紧凑布局，动画只围绕数字区域。
- `prefers-reduced-motion` 下三类动画均缩短并移除抖动。

## 建议结论

采用三分量事件、两种主反馈加一条弱化输出反馈：缓存命中与未命中均可辨识，输出费用单独解释；余额按事件总费用一次更新；同一轮多个分量进入共同 FIFO 轨道播放；保留 `damageKind` 作为双向版本兼容回退。
